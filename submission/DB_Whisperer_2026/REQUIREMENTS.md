# DB Whisperer Final Report and Standalone Website Requirements

This checklist is based on the course's 2026 final-assignment instructions and keeps only the standalone website submission requirements.

## 1. Final Report

The final report must address every section below in detail.

### 1.1 Research Question, Objectives, and Significance

- State the engineering problem the project aims to solve.
- Explain why the problem is important.
- Define the project objectives and expected contribution.

### 1.2 Engineering Background and Proposed Method

Describe:

- The proposed approach or method.
- The system architecture.
- The algorithms used.
- The tools and technologies used.

### 1.3 Implementation and Evaluation

Describe:

- The system inputs.
- The information-processing process, including preprocessing where relevant.
- The main system components.
- The results.
- A comparison with relevant baselines, where possible.
- A discussion of the findings.

The evaluation must make the final score and main measures easy to find. It should also explain how the evaluation evolved, including why Benchmark V3 replaced earlier versions and what changed in its ambiguity definitions, scoring rules, and evidence controls.

### 1.4 Development Process, Challenges, and Lessons Learned

Describe:

- The stages of development.
- The main design decisions.
- Challenges encountered during development.
- The solutions selected to address those challenges.
- Professional and engineering lessons learned.

Also document the development team's thought process and human-in-the-loop role. Include the important dilemmas, alternatives considered, reasons for the chosen decisions, manual review of evaluation evidence, corrections or exclusions made, and how those judgments influenced Benchmark V3 and the final conclusions.

### 1.5 Conclusion and Future Work

Include:

- The main conclusions.
- Advantages and disadvantages of the solution.
- Research and implementation limitations.
- Possible directions for future expansion and development.

### 1.6 User Manual

Include:

- System requirements and dependencies.
- Installation and execution instructions.
- Required inputs.
- Automatic and manual operating steps.
- Expected outputs.
- The structure of the codebase or repository.

### 1.7 Papers Read

For each paper, include a link and:

1. One short paragraph describing the paper's purpose, proposed approach, main contribution, and main findings.
2. One paragraph explaining how the paper was used or applied in this project.

## 2. Standalone Website

### 2.1 Required Content

- Include all report materials and presentations on the website.
- State the group members' names and the project topic.
- Do not include student identification numbers in the website, final report, presentations, or any other uploaded document.

### 2.2 Language and Presentation

- Write the website in proper English.
- Materials written in Hebrew may be downloadable, but their links must be labeled `(in Hebrew)`.
- Divide the website into clear topics and subtopics.
- Keep it readable, easy to navigate, visually consistent, and aesthetically pleasing.
- Do not require visitors to install specialized software.

### 2.3 ZIP Structure

- Submit the website as a ZIP archive named with the project name and course-completion year: `DB_Whisperer_2026.zip`.
- The ZIP must contain exactly one top-level directory.
- That directory must have the same name as the ZIP without `.zip`: `DB_Whisperer_2026/`.
- The main website file inside that directory must be named `index.htm`.
- All links must use paths relative to the submitted directory structure.

Expected package shape:

```text
DB_Whisperer_2026.zip
└── DB_Whisperer_2026/
    ├── index.htm
    ├── assets/
    ├── papers/
    ├── presentations/
    └── reports/
```
