Interactive Natural-Language Database Exploration

Query CSV-based databases with LLM-generated SQL, schema context, and ambiguity clarification.

DB Whisperer allows users to explore CSV-based databases using natural language. The system loads data into DuckDB, generates read-only SQL through an LLM-based workflow, detects ambiguous requests, and displays query results through a Streamlit interface.

Papers We Studied

The project connects academic research about LLM-based software engineering with a practical system for database exploration.

CODEXGRAPH: Bridging Large Language Models and Code Repositories via Code Graph Databases

Presented by: Ohad Livay, Yotam Katz

CODEXGRAPH explores how graph database representations can help LLMs understand and interact with code repositories more effectively. Its central idea is that structured knowledge can improve retrieval, reasoning, and repository-scale software tasks.

Contribution to our project: DB Whisperer similarly uses structured schema metadata and discovered relationships to provide better context for LLM-based reasoning.

ClarifyGPT: Empowering LLM-based Code Generation with Intention Clarification

Presented by: Tali Ratner, Liran Becher

ClarifyGPT focuses on improving LLM-based code generation by asking clarification questions when user intent is ambiguous. The paper motivates interactive clarification instead of assuming the first interpretation is correct.

Contribution to our project: This idea directly connects to DB Whisperer’s ambiguity-handling workflow for natural-language database questions.

The System We Built

DB Whisperer is organized around CSV ingestion, schema analysis, SQL generation, ambiguity detection, and result display.

1

CSV Input

The user provides one or more CSV files to explore.

2

ETLer

The system imports CSV data into DuckDB and extracts schema metadata.

3

User Question

The user asks a natural-language question about the data.

4

Querier

The system generates read-only DuckDB SQL using database context and OpenRouter.

5

Ambiguity Handling

The system checks whether the request has multiple valid interpretations and may ask for clarification.

6

Results Display

The final SQL is executed and the result is displayed in the Streamlit interface.

Technologies

  • Python for the implementation.
  • Streamlit for the user interface.
  • DuckDB for CSV-based analytical querying.
  • OpenRouter for LLM access.
  • Requests and pytz as supporting dependencies.

Engineering Challenges

  • Translating vague natural language into valid SQL.
  • Handling ambiguous user requests.
  • Discovering relationships between CSV tables.
  • Restricting execution to read-only SQL.
  • Managing prompts, SQL candidates, and LLM responses.

User Manual

Basic usage instructions for the live demo and local execution.

Using the Live Demo

  1. Get an API key from OpenRouter.
  2. Open the DB Whisperer live demo.
  3. Start chatting with the database.

The API key is used for the current session and is not saved by the application.

Running Locally

Install dependencies and run the Streamlit application:

python -m pip install -r requirements.txt
streamlit run app.py

Inputs

  • CSV file or files.
  • Natural-language question.
  • OpenRouter API key/configuration.

Outputs

  • Generated SQL query.
  • Query result.
  • Clarification question when ambiguity is detected.
